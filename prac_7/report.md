## 1. Цель работы

Освоить построение одностраничного интерфейса с вкладками, обработкой событий и динамической сменой содержимого без полной перезагрузки страницы: управление DOM, организация навигации, хранение данных представлений в JavaScript, обработка пустых и некорректных данных.

## 2. Варианты и требования к интерфейсу

| № | Уровень | Приложение | Вкладки | Действие по варианту |
|---|---------|------------|---------|----------------------|
| 7 | Базовый | Спортклуб | Тренировки, Тренеры, Абонементы | Активная вкладка оформляется CSS |
| 12 | Средний | Новости факультета | Новости, События, Объявления | Фильтр по ключевому слову |
| 18 | Повышенный | Панель заказов | Новые, В работе, Готовые | Смена статуса заказа, счётчики по вкладкам |

Общие требования, выполненные во всех проектах:

- один `index.html`, отдельные `style.css` и `app.js`, три вкладки;
- переключение без перезагрузки страницы, обработка клика через `addEventListener()`;
- контент создаётся средствами DOM из массивов и объектов JavaScript;
- активная вкладка выделяется (`.active`, `aria-selected`);
- узкий экран: вкладки прокручиваются по горизонтали, карточки перестраиваются (`grid` с `auto-fit`);
- фреймворки и jQuery не используются; пользовательские данные выводятся через `textContent`.

## 5. Ключевые фрагменты кода

### 5.1. Переключение вкладок (общее для всех вариантов)

```js
function show(name) {
  tabs.forEach(b => {
    const on = b.dataset.page === name;
    b.classList.toggle("active", on);
    b.setAttribute("aria-selected", on);
  });
  render(name);
  try { localStorage.setItem(KEY, name); } catch (e) {}
}
tabs.forEach(b => b.addEventListener("click", () => show(b.dataset.page)));
```

Вкладка определяется по `data-page`, содержимое перерисовывается без перезагрузки страницы.

### 5.2. Создание карточек из данных (вариант 7)

```js
const card = el("article", "card");
card.append(el("h3", "", i.title), el("p", "meta", i.meta), el("p", "", i.text));
```

Функция `el()` создаёт элемент и задаёт текст через `textContent`, поэтому произвольный HTML в данных не исполняется.

### 5.3. Фильтр по ключевому слову (вариант 12)

```js
const q = search.value.trim().toLowerCase();
const items = all.filter(i =>
  !q || (i.title + " " + i.text + " " + i.tags.join(" ")).toLowerCase().includes(q));
count.textContent = `Найдено: ${items.length} из ${all.length}`;
```

Фильтр срабатывает по событию `input` и действует на текущую вкладку.

### 5.4. Смена статуса и счётчики (вариант 18)

```js
function setStatus(id, status) {
  const o = orders.find(x => x.id === id);
  if (o) o.status = status;
  render();
}
function updateCounters() {
  Object.keys(LABELS).forEach(s => {
    document.querySelector("#cnt-" + s).textContent =
      orders.filter(o => o.status === s).length;
  });
}
```

Заказ хранится в одном массиве, вкладка лишь фильтрует его по статусу, поэтому перенос между разделами сводится к изменению поля `status`.

## 8. Творческое задание

Во всех вариантах реализовано **запоминание последней открытой вкладки в `localStorage`**: при обновлении страницы пользователь возвращается в тот раздел, где закончил. Обращение к хранилищу обёрнуто в `try/catch`, поэтому при его недоступности приложение продолжает работать со стартовой вкладкой. В варианте 7 дополнительно сделана **клавиатурная навигация** по вкладкам (←, →, Home, End), в варианте 18 — **динамические счётчики** на вкладках.

## 9. Ответы на контрольные вопросы

1. **SPA** — приложение, где переходы между разделами выполняются внутри одной HTML-страницы, а содержимое меняется скриптом. В многостраничном сайте каждый переход загружает новую страницу целиком.
2. Слушатель клика на кнопке вкладки заменяет содержимое контейнера средствами DOM, переход по ссылке не выполняется.
3. Элемент находят через `document.querySelector()` или `querySelectorAll()`, изменяют через `textContent`, `classList`, `append()`, `replaceChildren()`.
4. `addEventListener()` подписывает обработчик на событие, не затирая другие обработчики этого элемента, и разделяет разметку и логику.
5. Data-атрибуты хранят служебные данные в HTML (`data-page="home"`), читаются через `element.dataset.page`.
6. `textContent` вставляет строку как текст, `innerHTML` разбирает её как HTML, что при пользовательских данных открывает путь к XSS.
7. Активной вкладке добавляют CSS-класс (`.active`) и атрибут `aria-selected`, остальным снимают.
8. Данные хранят в объекте, где ключ — имя раздела, а значение — массив записей; общий код отрисовки обходит нужный массив.
9. `fetch()` запрашивает ресурс по сети и возвращает Promise. При открытии через `file://` браузер блокирует такие запросы по соображениям безопасности, поэтому проект запускают через локальный HTTP-сервер (например, `python -m http.server`).
10. Ошибку ловят через `catch` или проверку `response.ok`, показывают пользователю понятное сообщение и состояние загрузки.
11. Проверяют клавишей Tab: фокус должен проходить по вкладкам в логичном порядке, быть виден, а Enter/пробел должны активировать вкладку.
12. Плюсы: нет перезагрузок, быстрый отклик, нет зависимостей, понятен принцип работы. Ограничения: приходится вручную управлять состоянием и перерисовкой, сложнее поддерживать большой проект, нужно отдельно заботиться об адресе страницы (история, закладки) и SEO.
