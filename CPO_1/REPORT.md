## 1. Исследование предметной области

### 1.1 Проблема и актуальность
Контакты хранятся в разных местах: SIM-карта, мессенджеры, заметки, бумажные записи. Из-за этого возникают дубликаты, устаревшие номера и трудности с поиском. Студенту и сотруднику нужен простой инструмент, который хранит карточки, быстро находит нужную и позволяет разбивать контакты по группам (семья, учёба, работа).

### 1.2 Целевая аудитория
Студенты и преподаватели, которым нужна лёгкая локальная адресная книга без регистрации, облака и рекламы.

### 1.3 Обзор аналогов
| Аналог | Сильные стороны | Ограничения |
|---|---|---|
| Google Контакты | синхронизация, метки, объединение дубликатов | требует аккаунт и интернет, избыточен для учебных задач |
| Контакты (iOS / Android) | интеграция с телефоном, быстрый поиск | привязка к платформе, сложно переносить данные |
| Microsoft Outlook (Люди) | группы рассылки, интеграция с почтой | сложный интерфейс, корпоративная ориентация |

> ⚠️ Перед сдачей проверьте таблицу по актуальным версиям этих сервисов и добавьте ссылки на официальные страницы (в задании требуется минимум 3 источника).

### 1.4 Поля контактной карточки
По итогам анализа выбраны поля: **ID, имя, телефон, e-mail, группа, заметка**. Обязательные: имя и телефон. Остальные необязательные.

### 1.5 Ограничения решения
Консольный интерфейс, локальное хранение в JSON, один пользователь, без синхронизации и импорта.

## 2. Требования

### Функциональные
| № | Требование |
|---|---|
| F1 | Добавление контакта с проверкой данных |
| F2 | Редактирование отдельных полей контакта |
| F3 | Удаление контакта с подтверждением |
| F4 | Поиск по имени, телефону (в любом формате записи) и e-mail без учёта регистра |
| F5 | Группировка контактов по группам со счётчиком |
| F6 | Сохранение и загрузка данных между запусками |

### Нефункциональные
| № | Требование |
|---|---|
| NF1 | Программа не падает при любом некорректном вводе, а показывает понятное сообщение |
| NF2 | Запуск без сторонних библиотек (только стандартная библиотека Python 3.10+) |
| NF3 | Данные хранятся в читаемом формате JSON (UTF-8) |

### Пользовательские сценарии
1. **Добавление.** Пользователь выбирает «Добавить», вводит имя, телефон, группу и получает подтверждение.
2. **Поиск.** Пользователь вводит фрагмент имени или номера и видит подходящие карточки.
3. **Исправление.** Пользователь меняет телефон контакта, оставляя остальные поля пустым вводом.

### Критерии приёмки
Все 13 автотестов проходят (в том числе ошибочный ввод и граничные значения); данные сохраняются между запусками; для каждого сценария есть реакция на неверный ввод.

## 3. Проектирование

### 3.1 Модель жизненного цикла: инкрементная
Выбрана **инкрементная модель**. Функциональность небольшая и делится на независимые части, каждую из которых можно реализовать и проверить отдельно:

| Инкремент | Содержание |
|---|---|
| 1 | Модель данных, добавление, просмотр |
| 2 | Валидация ввода |
| 3 | Поиск, редактирование, удаление |
| 4 | Группировка, сохранение в JSON |
| 5 | Тесты, документация |

Каскадная модель менее удобна: требования уточнялись по ходу (например, формат телефона), а возвращаться к прошлым этапам в ней сложно. Спиральная и Agile рассчитаны на крупные проекты и команду, для индивидуального мини-проекта они избыточны.

### 3.2 Архитектура модулей
```
Консольный интерфейс (main, show, ask_id)
            │
   Класс ContactBook (add / update / delete / search / by_group / save / load)
            │
 Функции валидации (validate_name, normalize_phone, validate_email, parse_group)
            │
 Структуры данных: Contact (dataclass), Group (Enum), список + JSON-файл
```

### 3.3 Структуры данных (лекции 6 и 8)
- `Contact`: структура (`dataclass`) с полями id, name, phone, email, group, note.
- `Group`: перечисление (`Enum`) из 5 групп.
- Список `list[Contact]` для хранения; словарь `{группа: [контакты]}` для группировки.

### 3.4 Ключевые алгоритмы
- **Нормализация телефона (строки, лекция 7):** проверка допустимых символов → выделение цифр циклом → проверка длины 10–15 → добавление `+`, если он был в начале. Поэтому `+7 (701) 123-45-67` и `87011234567` приводятся к единому виду.
- **Поиск (циклы, лекция 4):** запрос приводится к нижнему регистру; контакт подходит, если запрос встречается в имени или e-mail либо цифры запроса встречаются в телефоне; результат сортируется по имени.
- **Группировка:** создаётся словарь со всеми группами, контакты распределяются одним проходом по списку, внутри групп сортировка по имени.
- **Контроль дубликатов:** при добавлении и редактировании телефон сравнивается с телефонами остальных контактов.

## 4. Реализация

| Тема лекций | Где применено |
|---|---|
| Циклы (4) | цикл меню, перебор контактов в поиске и группировке, выделение цифр |
| Функции (5) | `validate_*`, `normalize_phone`, `parse_group`, `show`, `ask_id`, `main` |
| Массивы / коллекции (6) | список контактов, словарь групп |
| Строки (7) | `split/join`, `title`, `lower`, регулярные выражения, `isdigit` |
| Структуры и перечисления (8) | `Contact` (dataclass), `Group` (Enum) |

Обработка ошибок: собственное исключение `ValidationError` перехватывается в главном цикле, программа печатает «Ошибка: …» и продолжает работу. Также обработан повреждённый файл данных.

**Запуск:** `python src/contacts.py`
